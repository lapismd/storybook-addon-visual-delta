# Storybook Reload and Visual Delta Readiness

> Historical implementation record. Use the
> [`Visual Delta system specification`](./specs/index.md) for the normative
> contract.

## Goal

Keep Visual Delta provisional until the current preview render has completed,
and keep one Storybook supervisor per checkout and port lane. Visual baselines
remain compare-only and must not be regenerated by this work.

## Reproduced causes

- An existing AI baseline was temporarily shown as missing after refresh. The
  manager fallback treated an incompletely hydrated Storybook parameters entry
  as proof that the baseline was absent.
- Five `storybook-run.mjs` supervisors from this checkout were watching the
  same source tree and relaunching children on port 9009. `storybook:stop`
  stopped the listener but did not stop those supervisors.
- The addon source watcher sent an unconditional Vite full-page reload while
  the Storybook wrapper also restarted for manager, shared, and node changes.

## Slice 1: preview readiness

- [x] Give every preview render an HMR-safe generation.
- [x] Include the current completion state in every `INIT_IMAGE`, including
      responses to `REQUEST_INIT_IMAGE`.
- [x] Mark readiness only from Storybook's exact `storyFinished` event.
- [x] Model baseline availability as unknown, present, or absent.
- [x] Keep capture and mutation actions disabled until the current generation
      is ready.
- [x] Ignore stale story or generation events.
- [x] Cover provisional, present, absent, replay, and stale transitions with
      focused tests.
- [x] Add manager browser coverage for delayed missing and existing AI
      baselines.

## Slice 2: process ownership and reloads

- [x] Store checkout-and-port ownership in ignored cache state.
- [x] Reuse an existing matching Storybook server on duplicate start.
- [x] Make restart explicitly replace the matching owner.
- [x] Stop matching supervisors and descendants, including legacy orphans,
      before falling back to port cleanup.
- [x] Release watchers and ownership when the Storybook child exits.
- [x] Let preview source use Vite HMR; debounce one restart for addon
      manager/shared/node changes.
- [x] Keep the expensive affected-story bootstrap scan behind preview
      readiness and cache its result across manager reloads until source or
      graph inputs change.
- [x] Cover ownership, stale state, stop, restart, child exit, and alternate
      ports with focused tests.
