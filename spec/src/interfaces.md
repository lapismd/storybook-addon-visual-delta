# Visual Delta interfaces

This reference defines the package exports, command-line interface, development HTTP surface, Storybook events, browser markers, and progress protocols. Callers may depend on these contracts, but not on undeclared source paths.

## Normative requirements

These requirements keep callers on validated, recoverable interfaces.

| ID         | Requirement                                                                                                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| VD-API-001 | Portable consumers MUST use declared package exports. Internal source paths are not stable unless `package.json` exports them for a named integration purpose.                  |
| VD-API-002 | The command-line interface MUST reject conflicting selection flags, require exact targets for writes, and preserve compare-only behavior for `test`.                            |
| VD-API-003 | Development HTTP routes MUST validate method, payload, target, and host capability before acting. Mutation routes MUST reject static or unsupported hosts.                      |
| VD-API-004 | Storybook channel events MUST carry serializable state and tolerate manager or preview remounts. A remount MUST be able to request current state again.                         |
| VD-API-005 | Query parameters and DOM attributes MUST identify exact story, interaction, readiness generation, and capture settings. Stale markers MUST be cleared on navigation or remount. |
| VD-API-006 | Long-running actions MUST expose structured progress, streamed runner logs, and a terminal result. `POST /compare-story` MUST forward capture-runner log chunks, including ANSI formatting, through its unchanged text NDJSON response so Diff Browser can present them while the exact-story comparison is running. Formatting MUST remain presentation data rather than change the stream event contract. Reconnection MUST not start a duplicate run. |
| VD-API-007 | The portable package identifier MUST be `@lapismd/storybook-addon-visual-delta`. Package documentation, Storybook registration, public import examples, and files generated by `visual-delta init` MUST use that identifier and its declared subpaths. Its release manifest MUST permit public npm publication, declare the canonical `lapismd/storybook-addon-visual-delta` GitHub repository, and retain the executable `visual-delta` bin mapped to `./dist/node/cli.js` in the packed artifact. A packed dependency MAY include exported source files without source-build configuration; executing those files MUST stage the shipped `dist/node/cli.js` worker without requiring an omitted TypeScript configuration. |
| VD-API-008 | Browser-aware CLI, HTTP, progress, story-fact coverage, and result contracts MUST identify the selected `{ browser }` target separately from `VisualCaptureProfile` provenance and identify browser versus cached-actual comparison. `POST /compare-story` MUST accept an explicit target for non-canonical teaching assets whose URLs do not encode a browser, require it to match the selected browser, and keep a canonical filename suffix authoritative. Compare-only resolution MAY read that PNG beneath `snapshotDir`; mutation and cached-actual reuse MUST reject non-canonical targets. Existing Chromium and deprecated environment aliases MAY remain, but platform MUST NOT participate in baseline identity. A project-owned runner MUST receive a frozen manifest and return progress, matching profile metadata, one terminal result, and checksummed staged artifacts. Test results MAY stage only version 4 result JSON, matching actual/diff diagnostics, and exact affected-planning files; mutations MAY stage only artifacts permitted by their operation. |
| VD-API-009 | `GET /config` MUST expose a de-duplicated project-wide browser inventory derived from canonical browser-qualified PNG filenames beneath the configured `snapshotDir`, plus the resolved canonical capture profile and runner availability. Discovery MUST ignore legacy platform-qualified PNGs, actual/diff diagnostics, non-PNG files, unsupported browser suffixes, and files outside that directory; a missing or unreadable directory MUST yield an empty inventory without weakening configuration diagnostics. |
| VD-API-010 | `POST /story-facts` version 4 MUST preserve aggregate coverage and result-hash fields while adding project `availableBrowsers`, required configured browsers, and exact per-story primary `browserCoverage`. Managers MUST accept older responses without inventing browser coverage. The `visualFilter` query contract MUST accept `browser.<id>`, its existing `!` exclusion form, and the include-only `quick.browser-coverage-gaps` token; OS tokens and OS-parity filtering are obsolete. |

## Command-line interface

The supported commands are:

| Command                           | Required intent                                       | Write behavior                                              |
| --------------------------------- | ----------------------------------------------------- | ----------------------------------------------------------- |
| `visual-delta init`               | Scaffold missing suite and configuration files        | Writes missing files, or existing files only with `--force` |
| `visual-delta test --all`         | Compare every eligible visual story                   | Never updates snapshots                                     |
| `visual-delta test --affected`    | Compare the conservative affected selection           | Never updates snapshots                                     |
| `visual-delta test --story-id`    | Compare an exact, repeatable story selection           | Never updates snapshots or broadens an empty selection      |
| `visual-delta update`             | Create or overwrite exact primary baselines           | Requires approval and an exact story or component target    |
| `visual-delta interaction-update` | Create or overwrite one interaction baseline          | Requires approval, story ID, and interaction label          |
| `visual-delta skip`               | Add `skip-visual` to an exact story or component      | Mutates only matching story sources                         |
| `visual-delta include`            | Remove `skip-visual` from an exact story or component | Mutates only matching story sources                         |
| `visual-delta harness doctor`     | Validate the resolved runner and canonical profile   | Read-only diagnostics                                       |
| `visual-delta migrate-baselines`  | Inventory or apply browser-only filename migration   | Apply requires `--approved`; dry-run is read-only           |

`--dry-run` and `--explain` MUST avoid builds and captures for affected planning. `--create-only` MUST use missing-only snapshot mode. `--story-id` MAY repeat only where the command accepts an exact list. `test` accepts exactly one of `--all`, `--affected`, or one-or-more `--story-id` values, plus repeatable `--browser chromium|firefox|webkit`, `--failure-mode warn|strict`, and one-shot `--fresh`; update commands accept one exact `--browser`. Middleware MAY add a traversal-safe `--baseline-rel` beneath `snapshotDir` only for one exact compare-only teaching target, and MAY forward configured Playwright invocation arguments as repeatable `--visual-test-arg` values. An omitted browser selection resolves to the configured browser list for tests and to Chromium for backward-compatible mutation commands. `migrate-baselines` MUST refuse collisions and mutation without both `--apply` and `--approved`; an optional repeatable `--cache-dir` identifies affected caches to invalidate after an approved cutover.

## Development HTTP routes

All routes use the `/__visual-delta` prefix:

| Method       | Path                           | Responsibility                                                       |
| ------------ | ------------------------------ | -------------------------------------------------------------------- |
| `GET`        | `/runtime`                     | Return the stable dev-server instance identity                       |
| `GET`, `PUT` | `/config`                      | Read resolved configuration or write validated project configuration |
| `PUT`        | `/story-configuration`         | Write allow-listed overrides for one story                           |
| `POST`       | `/playwright-threshold`        | Write the host Playwright threshold                                  |
| `POST`       | `/story-facts`                 | Resolve coverage and source facts for exact story IDs                |
| `POST`       | `/init`                        | Scaffold portable integration files                                  |
| `POST`       | `/rebuild-static`              | Build static Storybook without capture                               |
| `POST`       | `/create-baseline`             | Create missing baselines for frozen IDs                              |
| `POST`       | `/update-baseline`             | Overwrite requested baselines for frozen IDs                         |
| `POST`       | `/create-interaction-baseline` | Write one interaction baseline and wiring                            |
| `POST`       | `/delete-baseline`             | Delete one exact baseline and its sidecars                           |
| `POST`       | `/capture-subject`             | Stream a host-local diagnostic subject capture; legacy Chromium requests remain valid |
| `POST`       | `/compare-story`               | Run an authoritative exact-story configured-browser comparison       |
| `POST`       | `/review-status`               | Set independent review metadata                                      |
| `POST`       | `/skip-visual`                 | Add or remove skip eligibility                                       |
| `POST`       | `/action-scope`                | Resolve and freeze exact Testing Module IDs                          |
| `GET`        | `/affected-plan`               | Return the current conservative selection and reasons                |
| `POST`       | `/run-tests`                   | Start one compare-only Playwright run                                |
| `GET`        | `/run-events`                  | Replay and continue an in-flight or recent run                       |
| `GET`        | `/run-status`                  | Return current or last run phase and progress                        |
| `POST`       | `/cancel-tests`                | Request cancellation of an in-flight run                             |
| `GET`        | `/baseline-history`            | List committed revisions for one baseline                            |
| `GET`        | `/baseline-history/image`      | Return one historical baseline image                                 |
| `GET`        | `/baseline-history/diff`       | Return source changes between revisions                              |
| `GET`        | `/change-sets`                 | List UI-driven mutations and commit state                            |
| `GET`        | `/change-set-file`             | Return stable before-and-after file content                          |
| `POST`       | `/change-set-commit`           | Commit one validated complete change set                             |

Read routes MUST reject path traversal. Write routes MUST report the exact changed files. Streaming responses use newline-delimited JSON (NDJSON) where the caller needs incremental progress.

`POST /compare-story` accepts an explicit `target: { browser }` when story
metadata identifies a non-canonical teaching baseline whose URL has no browser
suffix. The request target and selected browser MUST match. When the URL has a
canonical browser suffix, that suffix remains authoritative and conflicting
explicit metadata MUST fail rather than select another browser's baseline. The
read-only comparison route may resolve that explicitly targeted PNG at its exact
traversal-safe location beneath the mounted snapshot directory. This exception
does not make the asset a canonical baseline and MUST NOT be reused by create,
update, or delete routes.

`POST /compare-story` MUST translate the exact story, browser, interaction,
mode, and selected baseline into the corresponding compare-only
`visual-delta test` worker request and run it through the resolved capture
runner. `POST /run-tests` MUST use the same worker and runner for its frozen
scope. Neither route may launch a separate middleware-local Playwright browser.
Returned sidecars MUST carry the same capture profile as the runner terminal
result before they can be exposed as authoritative evidence. The compare-story
NDJSON stream MUST retain runner log chunks independently from coarse progress
labels and deliver them to the manager before the terminal result.

`POST /capture-subject` is a compatibility diagnostic. Its host-local capture
MUST identify the selected browser and actual host platform, MUST NOT claim a
canonical capture profile, and MUST NOT supply authoritative comparison
evidence.

`POST /story-facts` version 4 returns observed canonical baseline browsers as
`availableBrowsers`, configured coverage requirements as `requiredBrowsers`,
and exact primary `browserCoverage` on each story. Existing aggregate
`baseline`, `baselineHash`, `resultBaselineHash`, and
`resultCaptureConfigHash` fields retain their established meaning. Version 3
environment fields MAY be accepted as compatibility input, but managers MUST
reduce them to browser evidence and MUST NOT restore OS identity or parity.

## Storybook channel events

The channel namespace is `visual-delta`. Events are grouped by responsibility:

| Direction          | Events                                                                                                                                                                                                                                  |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Preview to manager | `init-image`, `preview-ready`, `overlay-info`, `overlay-hidden`, `overlay-listener-ready`, `play-steps`, `visual-capture-parked`, `ignore-regions-status`, `split-zoom-status`, `baseline-geometry-status`, `baseline-alignment-status` |
| Manager to preview | `request-init-image`, `select-image`, `update-overlay-style`, `reset-overlay`, `request-overlay-info`, `hide-overlay`, `show-overlay`, `run-until-step`, `set-highlight-ignore`, `config-updated`                                       |

`overlay-listener-ready` MUST trigger replay of the current selection. `request-init-image` MUST allow a remounted manager to recover current preview state.

## Query parameters and DOM markers

The preview and capture processes use:

| Surface           | Name                                       | Meaning                                        |
| ----------------- | ------------------------------------------ | ---------------------------------------------- |
| Iframe query      | `id`                                       | Exact Storybook story ID                       |
| Iframe query      | `viewMode=story`                           | Canvas story render                            |
| Iframe query      | `visualCaptureUntil`                       | Park after a named interaction ID              |
| Iframe query      | `visualCaptureCall`                        | Replay through one exact instrumenter call     |
| Root attribute    | `data-visual-delta-story-finished`         | Exact story ID whose render and play completed |
| Root attribute    | `data-visual-delta-delay`                  | Resolved settle delay                          |
| Root attribute    | `data-visual-delta-align`                  | Resolved viewport or canvas alignment          |
| Root attribute    | `data-visual-delta-ignore-selectors`       | Serialized ignore selectors                    |
| Root attribute    | `data-visual-delta-crop-to-viewport`       | Viewport capture flag                          |
| Root attribute    | `data-visual-delta-diff-threshold`         | Resolved pixel color threshold                 |
| Root attribute    | `data-visual-delta-diff-include-aa`        | Resolved anti-aliasing policy                  |
| Root attribute    | `data-visual-delta-pass-threshold-percent` | Resolved differing-pixel allowance             |
| Root attribute    | `data-visual-delta-modes`                  | Serialized named-mode definitions              |
| Root attribute    | `data-visual-capture-step`                 | Most recently completed named step             |
| Root attribute    | `data-visual-capture-ready`                | Interaction ID at which play is parked         |
| Element attribute | `data-visual-delta-ignore`                 | Ignore this element’s painted region           |

Chromatic-compatible ignore markers MAY supplement `data-visual-delta-ignore`. The implementation MUST union and de-duplicate matched painted regions.

## Run progress protocol

A run has one stable job identity. Progress events SHOULD include phase,
completed count, total count, current story, browser target, capture profile,
message, policy outcome, warning count, and terminal outcome when known.

The manager MAY reconnect after hot-module replacement or remount. It MUST query status, replay stored events, and continue from the existing job rather than issuing another `/run-tests` request.
