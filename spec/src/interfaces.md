# Visual Delta interfaces

This reference defines the package exports, command-line interface, development HTTP surface, Storybook events, browser markers, and progress protocols. Callers may depend on these contracts, but not on undeclared source paths.

## Normative requirements

These requirements keep callers on validated, recoverable interfaces.

| ID         | Requirement                                                                                                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| VD-API-001 | Portable consumers MUST use declared package exports. Internal source paths are not stable unless `package.json` exports them for a named integration purpose.                  |
| VD-API-002 | The command-line interface MUST reject conflicting selection flags, require exact targets for writes, and preserve compare-only behavior for `test`.                            |
| VD-API-003 | Development HTTP routes MUST validate method, payload, target, and host capability before acting. Mutation routes MUST reject static or unsupported hosts.                      |
| VD-API-004 | Storybook channel events MUST carry serializable state and tolerate manager or preview remounts. A remount MUST be able to request current state again.                         |
| VD-API-005 | Query parameters and DOM attributes MUST identify exact story, interaction, readiness generation, and capture settings. Stale markers MUST be cleared on navigation or remount. |
| VD-API-006 | Long-running actions MUST expose structured progress and a terminal result. Reconnection MUST not start a duplicate run.                                                        |
| VD-API-007 | The portable package identifier MUST be `@lapismd/storybook-addon-visual-delta`. Package documentation, Storybook registration, public import examples, and files generated by `visual-delta init` MUST use that identifier and its declared subpaths. |

## Package exports

The supported public entry points are:

| Import                                        | Responsibility                                                           |
| --------------------------------------------- | ------------------------------------------------------------------------ |
| `@lapismd/storybook-addon-visual-delta`                | Package root and shared contract                                         |
| `@lapismd/storybook-addon-visual-delta/preset`         | Storybook preset, static mount, Vite integration                         |
| `@lapismd/storybook-addon-visual-delta/manager`        | Panel, toolbar tools, and Testing Module                                 |
| `@lapismd/storybook-addon-visual-delta/preview`        | Decorators, overlay channel, interaction park support                    |
| `@lapismd/storybook-addon-visual-delta/visual-capture` | Mid-play visual capture helper                                           |
| `@lapismd/storybook-addon-visual-delta/playwright`     | `defineVisualSuite` and Playwright configuration helpers                 |
| `@lapismd/storybook-addon-visual-delta/node`           | Middleware, path helpers, injection, affected planner, CLI orchestration |

The executable name is `visual-delta`.

## Command-line interface

The supported commands are:

| Command                           | Required intent                                       | Write behavior                                              |
| --------------------------------- | ----------------------------------------------------- | ----------------------------------------------------------- |
| `visual-delta init`               | Scaffold missing suite and configuration files        | Writes missing files, or existing files only with `--force` |
| `visual-delta test --all`         | Compare every eligible visual story                   | Never updates snapshots                                     |
| `visual-delta test --affected`    | Compare the conservative affected selection           | Never updates snapshots                                     |
| `visual-delta update`             | Create or overwrite exact primary baselines           | Requires approval and an exact story or component target    |
| `visual-delta interaction-update` | Create or overwrite one interaction baseline          | Requires approval, story ID, and interaction label          |
| `visual-delta skip`               | Add `skip-visual` to an exact story or component      | Mutates only matching story sources                         |
| `visual-delta include`            | Remove `skip-visual` from an exact story or component | Mutates only matching story sources                         |

`--dry-run` and `--explain` MUST avoid builds and captures for affected planning. `--create-only` MUST use missing-only snapshot mode. `--story-id` MAY repeat only where the command accepts an exact list.

## Development HTTP routes

All routes use the `/__visual-delta` prefix:

| Method       | Path                           | Responsibility                                                       |
| ------------ | ------------------------------ | -------------------------------------------------------------------- |
| `GET`        | `/runtime`                     | Return the stable dev-server instance identity                       |
| `GET`, `PUT` | `/config`                      | Read resolved configuration or write validated project configuration |
| `PUT`        | `/story-configuration`         | Write allow-listed overrides for one story                           |
| `POST`       | `/playwright-threshold`        | Write the host Playwright threshold                                  |
| `POST`       | `/story-facts`                 | Resolve coverage and source facts for exact story IDs                |
| `POST`       | `/init`                        | Scaffold portable integration files                                  |
| `POST`       | `/rebuild-static`              | Build static Storybook without capture                               |
| `POST`       | `/create-baseline`             | Create missing baselines for frozen IDs                              |
| `POST`       | `/update-baseline`             | Overwrite requested baselines for frozen IDs                         |
| `POST`       | `/create-interaction-baseline` | Write one interaction baseline and wiring                            |
| `POST`       | `/delete-baseline`             | Delete one exact baseline and its sidecars                           |
| `POST`       | `/capture-subject`             | Stream a legacy Chromium subject capture                             |
| `POST`       | `/compare-story`               | Run an authoritative exact-story Chromium comparison                 |
| `POST`       | `/review-status`               | Set independent review metadata                                      |
| `POST`       | `/skip-visual`                 | Add or remove skip eligibility                                       |
| `POST`       | `/action-scope`                | Resolve and freeze exact Testing Module IDs                          |
| `GET`        | `/affected-plan`               | Return the current conservative selection and reasons                |
| `POST`       | `/run-tests`                   | Start one compare-only Playwright run                                |
| `GET`        | `/run-events`                  | Replay and continue an in-flight or recent run                       |
| `GET`        | `/run-status`                  | Return current or last run phase and progress                        |
| `POST`       | `/cancel-tests`                | Request cancellation of an in-flight run                             |
| `GET`        | `/baseline-history`            | List committed revisions for one baseline                            |
| `GET`        | `/baseline-history/image`      | Return one historical baseline image                                 |
| `GET`        | `/baseline-history/diff`       | Return source changes between revisions                              |
| `GET`        | `/change-sets`                 | List UI-driven mutations and commit state                            |
| `GET`        | `/change-set-file`             | Return stable before-and-after file content                          |
| `POST`       | `/change-set-commit`           | Commit one validated complete change set                             |

Read routes MUST reject path traversal. Write routes MUST report the exact changed files. Streaming responses use newline-delimited JSON (NDJSON) where the caller needs incremental progress.

## Storybook channel events

The channel namespace is `visual-delta`. Events are grouped by responsibility:

| Direction          | Events                                                                                                                                                                                                                                  |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Preview to manager | `init-image`, `preview-ready`, `overlay-info`, `overlay-hidden`, `overlay-listener-ready`, `play-steps`, `visual-capture-parked`, `ignore-regions-status`, `split-zoom-status`, `baseline-geometry-status`, `baseline-alignment-status` |
| Manager to preview | `request-init-image`, `select-image`, `update-overlay-style`, `reset-overlay`, `request-overlay-info`, `hide-overlay`, `show-overlay`, `run-until-step`, `set-highlight-ignore`, `config-updated`                                       |

`overlay-listener-ready` MUST trigger replay of the current selection. `request-init-image` MUST allow a remounted manager to recover current preview state.

## Query parameters and DOM markers

The preview and capture processes use:

| Surface           | Name                                       | Meaning                                        |
| ----------------- | ------------------------------------------ | ---------------------------------------------- |
| Iframe query      | `id`                                       | Exact Storybook story ID                       |
| Iframe query      | `viewMode=story`                           | Canvas story render                            |
| Iframe query      | `visualCaptureUntil`                       | Park after a named interaction ID              |
| Iframe query      | `visualCaptureCall`                        | Replay through one exact instrumenter call     |
| Root attribute    | `data-visual-delta-story-finished`         | Exact story ID whose render and play completed |
| Root attribute    | `data-visual-delta-delay`                  | Resolved settle delay                          |
| Root attribute    | `data-visual-delta-align`                  | Resolved viewport or canvas alignment          |
| Root attribute    | `data-visual-delta-ignore-selectors`       | Serialized ignore selectors                    |
| Root attribute    | `data-visual-delta-crop-to-viewport`       | Viewport capture flag                          |
| Root attribute    | `data-visual-delta-diff-threshold`         | Resolved pixel color threshold                 |
| Root attribute    | `data-visual-delta-diff-include-aa`        | Resolved anti-aliasing policy                  |
| Root attribute    | `data-visual-delta-pass-threshold-percent` | Resolved differing-pixel allowance             |
| Root attribute    | `data-visual-delta-modes`                  | Serialized named-mode definitions              |
| Root attribute    | `data-visual-capture-step`                 | Most recently completed named step             |
| Root attribute    | `data-visual-capture-ready`                | Interaction ID at which play is parked         |
| Element attribute | `data-visual-delta-ignore`                 | Ignore this element’s painted region           |

Chromatic-compatible ignore markers MAY supplement `data-visual-delta-ignore`. The implementation MUST union and de-duplicate matched painted regions.

## Run progress protocol

A run has one stable job identity. Progress events SHOULD include phase, completed count, total count, current story, message, and terminal outcome when known.

The manager MAY reconnect after hot-module replacement or remount. It MUST query status, replay stored events, and continue from the existing job rather than issuing another `/run-tests` request.
